# テストは RSpec 流の階層で書く

## 指摘すること

describe / it で書くテストが、次の階層になっていなければ指摘する。

1. `describe`: テストの対象 (クラスやモジュール)
2. `describe`: メソッド。JS / TS では `total()` のように `()` を付ける。RSpec の `#total` は使わない
3. `describe`: 条件。「〜とき」で書く (RSpec の `context` に当たる)
4. `it`: 振る舞い。「〜を返す」「〜する」で書き、条件を含めない

条件のない基本の振る舞いは、条件の階層を挟まず、メソッドの直下に `it` を置く。1 つの `it` で確かめる振る舞いは 1 つにする (そのための expect は複数でもよい)。

## 理由

ユーザは BDD のスタイルを好み、RSpec の書き方を階層の規範にしている。JS / TS で `#` を避けるのは、`#` がプライベートメンバーの構文で、プライベートメソッドのテストに見えるため。

## 例

反している例:

```ts
describe('#total', () => {
  it('割引があるとき合計から割引を引く', ...);
});
```

沿っている例:

```ts
describe('Cart', () => {
  describe('total()', () => {
    it('商品の価格の合計を返す', ...);

    describe('割引があるとき', () => {
      it('合計から割引を引く', ...);
    });
  });
});
```
