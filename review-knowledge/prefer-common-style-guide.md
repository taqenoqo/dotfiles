# 書き方は独自ルールより一般的なスタイルガイドに従う

## 指摘すること

プロジェクトの文書に、言語の書き方についての独自ルールが書かれていたら指摘し、広く知られたスタイルガイド (TypeScript なら Google TypeScript Style Guide など) に従う形にするよう求める。コードが一般的なスタイルガイドから外れていて、その理由が書かれていない場合も指摘する。

## 理由

ユーザは、プロジェクト特有の書き方を決めるより、その言語で一般的とされる美しい書き方を好む。

## 例

反している例: 文書に「ユーティリティは必ずアロー関数で定義する」のような、独自の書き方のルールがある。

沿っている例: 文書には「書き方は Google TypeScript Style Guide に従う」とだけ書き、個別のルールは持たない。

## 当てはまらない場合

- 層の分け方など、書き方ではなく設計についての決定。
- テストの書き方のように、ユーザ自身がルール化を求めたもの。

## 出所

2026-11-15、TypeScript のプロジェクトで、AI が文書に独自の書き方のルールを足していったのに対し、「プロジェクト特有の設計方針を決めるのではなく、一般的な美しい書き方がいい」と指摘された。
