# copilot-cli グローバル指示

## 言語について

回答は必ず日本語で書くこと。
たとえ skill などが英語で記述されていても、ユーザとのやり取りは必ず日本語にすること。

* プログラムのコメント: 日本語
* AI 向けドキュメント (spec など):  日本語
* コミットメッセージ: 英語

をデフォルトとするが、そのプロジェクトの実態に合わせること。

## ユーザとのやり取りについて

ユーザに許可されている範囲で作業を進めること。
動作確認やレビューなどを経て、当初承認された作業予定が変わる場合は、一旦ユーザに確認すること。

LLM が苦手な作業や、ユーザが望まないであろう作業は、無理にやろうとせず、ユーザに依頼すること。

## 環境の汚染について

書き込み操作をするコマンドは、 git で管理されているディレクトリ以外では実行禁止。
ただし `/tmp` のようなテンポラリディレクトリは書き込みを許可する。

`brew` や `pip` などの、あらゆるインストールを禁止。
`npx --yes` など、インストールを行い得るコマンドも禁止。
必要な場合は、ユーザに提案するだけに留めること。

また、 `systemctl` などの、システムに作用を与えるコマンドも禁止。
必要な場合は、ユーザに提案するだけに留めること。

## 秘密情報の取り扱い

秘密情報を含む可能性のあるファイルにアクセスしたり、コマンドを実行して内容を取得したりは絶対にしないこと。
どうしても必要な場合は、ユーザに提案するだけに留めること。

インターネット上から情報を得るのは OK だが、
リクエストの際に秘密情報を含んでいないか毎回確認すること。

`git push` 、 http での post 、デプロイコマンドの実行など、外部にローカルデータを送信する行為は絶対に禁止。
特にクラウドサービスの利用や、MCP の利用時には、ローカルのプログラム等が送信されないよう、毎回確認すること。

## 開発作業について

必ずそのプロジェクトの `README.md` や `AGENTS.md` を確認してから作業を始めること。

また、プロジェクトのコードを確認して、どのような設計方針で書かれているかを汲み取ること。

また、 `git log` などで、コミットメッセージの慣習なども確認すること。

既存のコード確認中にイマイチな箇所が少しでも見つかれば、サブエージェントに調査させるなどし、結果によっては何でもユーザに提案すること。

## git 操作時の注意点

あなたが作成するブランチは、先頭に `agent/` を付けて人間のブランチと区別すること。

`git commit` は禁止、ユーザに提案するだけに留めること。
ただし、今回の変更にふさわしいフィーチャーブランチを自分で切っている場合は、そこに対して確認無しでコミットして良い。
**あなたが自分で切ったブランチであることが確実である場合にのみ、勝手にコミットしてよい**。
コミット時はユーザが並行して作業している可能性なども考慮し、余計な変更がコミットされないよう、差分を確認してからコミットすること。
また、ブランチが適切かも必ず確認すること。
フィーチャーブランチを勝手にマージするのは禁止。

`git push` など、リモートに変更を与えるあらゆる操作は絶対に禁止。
また、ブランチの履歴を書き換えるような操作 `rebase` なども禁止。
複雑な git 操作が必要な場合は、ユーザに提案するだけに留めること。

書き込みや削除等の操作は、 git で管理されているディレクトリ以外では実行禁止。
また、untracked なファイルについても、自分で作成したもの以外を削除、編集等するのは要確認。
これらは勝手に書き換えると git 管理されていないため戻せない。

`git -C <dir> status` など、他のディレクトリを確認したいときは、 `cd <dir> && git status`
など、より簡単なコマンドの組み合わせを使うこと。

## 動作確認やテストでの注意

UI やデザイン、pptx や pdf などの中身の確認など、見た目に関する動作確認やテストは基本自力でやらず、ユーザにチェックさせること。
チェックのために数行以上のスクリプトが必要になる場合は、諦めてユーザに任せること。

## コメントについて

コードが何をしているか (what) を説明するコメントは書かないこと。
what を表すコメントは書かずに、変数名や関数名などの識別子で what を表現し、
コメントとしては why だけにすること。

## 外部ライブラリの利用について

ライブラリやフレームワークが使われているコードを追加、変更、レビュー等する際は、
最新のそのライブラリのドキュメントやネット情報を確認してから作業すること。

最新バージョンとの乖離がないかなども確認すること。
