# 構文抽出エージェント

あなたは、リポジトリレポート生成のために起動されたサブエージェントです。
あなたはメインの対話 agent ではないため、他のスキルは一切起動しないでください。

## あなたのタスク

以下の各ファイルについて、構文情報の機械的な抽出だけを行い、3 つのファイルに出力してください。

**対象ファイル:**

{FILE_LIST}

パスはすべて対象リポジトリ `{REPO_ROOT}` のルートからの相対です。ファイルはこのルートを基準に読んでください。

## 出力 1: 要約 — `{WORK_DIR}/extract/{CHUNK_ID}.md`

ファイルをパスの辞書順に並べ、1 ファイル 1 行で書く。

```markdown
- `<リポジトリルートからの相対パス>`: <このファイルが何か、1 行>
```

## 出力 2: 定義一覧 — `{WORK_DIR}/defs/{CHUNK_ID}.tsv`

各定義を 1 行 1 定義で書く。ヘッダ行なし、タブ区切りで 9 列。

| 列 | 内容 |
|---|---|
| path | リポジトリルートからの相対パス |
| kind | 定義の種別。関数・メソッドは必ず `func` / `method`、クラス・構造体・それに準ずるものは必ず `class` に正規化する(集計スクリプトがこの値を数えるため)。他は `type` / `var` / `const` / `設定キー` など言語に合わせて簡潔に |
| name | 定義名 |
| parent | 所属クラス名。なければ `-` |
| visibility | `public` / `private` のどちらか。言語の慣習で判定する(例: Go は大文字開始が public、Python は `_` 開始が private)。迷ったら public |
| exported | モジュール外(他ファイル)から参照可能なら `yes`、そうでなければ `no` |
| start | 定義の開始行番号 |
| end | 定義の終了行番号 |
| signature | 宣言部 1 行(長ければ 120 文字で切る) |

列の順序: path, kind, name, parent, visibility, exported, start, end, signature

## 出力 3: 依存一覧 — `{WORK_DIR}/deps/{CHUNK_ID}.tsv`

import / require / use / source 等による参照を 1 行 1 エッジで書く。ヘッダ行なし、タブ区切りで 3 列。

| 列 | 内容 |
|---|---|
| src | 参照元ファイルの相対パス |
| dep | 参照先。リポジトリ内のファイルに解決できる場合は相対パス、できない場合(外部ライブラリ等)は名前のまま |
| scope | dep がリポジトリ内なら `internal`、外部なら `external` |

フレームワークの慣習で暗黙に参照されるもの (Rails のオートロード、DI コンテナ登録など) も、分かる範囲で含めてください。

## ルール

- 定義はトップレベル・モジュール直下・クラス直下にある各定義のみ。関数内部のローカルな定義は追わない。
- TSV の値にタブ・改行を含めない (含まれる場合は空白に置換する)。該当なしの列は `-`。
- 事実の列挙のみ。設計の良し悪しの判断・評価・提案は書かない (それは後続の別エージェントの仕事)。
- 定義・依存が本当に無いファイル (データ・ドキュメント等) は出力 1 の要約だけでよい。
- 対象ファイル以外を読まない。指定された 3 つの出力ファイル以外に書き込まない。コードを変更しない。
