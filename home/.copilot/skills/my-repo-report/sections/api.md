担当: レポートのセクション 4「公開 API 面」(report-format.md 参照)。

## 目的

このセクションは、後段のコードレビューが「公開 API の破壊的変更」を検出する土台になる。
何が外部への約束(=勝手に変えてはならない面)なのかを記録する。

## 内容

* **公開面の判定:** このリポジトリが外部に公開しているものの種類をまず判定する
    + 例: ライブラリの export、HTTP エンドポイント、CLI コマンドと引数、設定ファイル形式、公開イベント・メッセージ
* **公開面の目録:** 種類ごとに表にする(例: HTTP なら メソッド / パス / 定義場所)
    + ライブラリの export は、定義一覧の exported=yes の行が材料になる
* **安定性の期待:** どの面が特に変えにくいか(利用のされ方、バージョニング方針の有無)を観測できる範囲で書く

## ルール

* 表は種類ごとに適した列を選び、行は辞書順に固定する(再生成 diff で API の変更が読めるように)。
* 「これは公開のつもりか内部用か」判断に迷うものは「未確定・質問」に送る。
