担当: レポートのセクション 6「命名・コード慣習」(report-format.md 参照)。

## 内容

観測に基づく慣習を項目ごとに書く。

- ファイル名・ディレクトリ名の付け方
- 関数・型・定数の命名規則
- エラー処理のスタイル(例外 / Result 型 / エラーコード等)
- テストの置き場所・命名・使用フレームワーク
- コメント・ドキュメントの言語と密度
- lint / formatter 設定があればその要点

## ルール(このセクションで特に重要)

- **すべての断定に観測数を併記する。** 例: 「42 ファイル中 38 で snake_case」。観測数なしの「〜である」を書かない。
- 多数派と少数派が割れている場合は、割れていること自体を事実として書き、どちらが正かの判断は「未確定・質問」に送る。
- 観測は抽出結果(定義名の一覧)を第一とし、サンプリングで本文を確認する場合は「大きいファイル・多く参照されるファイル・新しいファイル」を優先して選ぶ。少数サンプルから全体を一般化しない。
