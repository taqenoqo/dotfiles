## 2. ディレクトリ構成と責務

トップレベル(必要なら 2 階層目まで)のディレクトリを表にする。

| パス | 責務 | 規模(ファイル数 / 行数の概数) |

責務は抽出結果の要約から導く。名前からの推測で書かない。

## 3. モジュール間依存

抽出結果の「依存」行を集計し、ディレクトリ(モジュール)単位の依存グラフを mermaid で書く。

- ノードはディレクトリ単位に丸める(ファイル単位にしない)
- 循環依存があれば明記する
- 依存の本数が極端に多い・少ないモジュールがあれば一言添える

## 4. レイヤ・境界規則

依存グラフから「観測される依存の向きの規則」を導く。

- 例: 「`ui/` → `core/` の依存が 24 件、逆向きは 0 件。core は ui に依存しない規則があるとみられる」
- 規則に対する例外(逆向き依存)があれば、件数と具体パスを列挙する
- 規則の「意図」は推測しない。意図の確認は「未確定・質問」に送る
