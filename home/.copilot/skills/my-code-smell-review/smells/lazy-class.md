# Lazy Class（怠け者クラス）

<https://refactoring.guru/smells/lazy-class>

## 兆候と症状

クラスを理解し、保守するには、常に時間とコストがかかる。にもかかわらず、その注意を払う価値がないほど仕事をしていないクラスなら、削除を検討すべきである。

## 原因

もともとは十分な役割を持つ想定で設計されたクラスでも、リファクタリングを重ねるうちに、拍子抜けするほど小さくなることがある。

あるいは、将来の拡張を見越して作られたものの、その予定されていた開発が結局行われなかったのかもしれない。

## 治療法

- ほとんど役に立っていないコンポーネントには [Inline Class](https://refactoring.guru/inline-class) を適用する
- 機能がほとんどないサブクラスには [Collapse Hierarchy](https://refactoring.guru/collapse-hierarchy) を試す

## 効果

- コード量を減らせる
- 保守しやすくなる

## 無視してよい場合

将来の開発意図を示すために *Lazy Class* が置かれていることもある。その場合は、コードの明快さと単純さのバランスを保つようにする。
