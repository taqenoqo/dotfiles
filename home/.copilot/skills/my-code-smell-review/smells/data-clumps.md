# Data Clumps（データの塊）

<https://refactoring.guru/smells/data-clumps>

## 兆候と症状

コードの異なる場所に、同じ変数のまとまり（たとえばデータベース接続用の引数群）が何度も現れる。こうした塊は独立したクラスにまとめるべきである。

## 原因

こうしたデータのまとまりは、プログラム構造のまずさや、いわゆる「copypasta programming」によって生まれることが多い。

あるデータ群が本当に Data Clumps か確かめたいなら、そのうちの1つの値を削除してみるとよい。残りの値だけでは意味が通らなくなるなら、その変数群は1つのオブジェクトとしてまとめるべき可能性が高い。

## 治療法

- 繰り返し現れるデータがクラスのフィールドなら、[Extract Class](https://refactoring.guru/extract-class) を使って専用クラスへ移す。
- 同じデータの塊がメソッド引数として繰り返し渡されるなら、[Introduce Parameter Object](https://refactoring.guru/introduce-parameter-object) でクラスにまとめる。
- データの一部を別メソッドへ渡しているなら、個々のフィールドではなくデータオブジェクト全体を渡せないか考える。[Preserve Whole Object](https://refactoring.guru/preserve-whole-object) が役立つ。
- それらのフィールドを使っているコードにも注目する。そのコードをデータクラスへ移したほうがよい場合もある。

## 効果

- コードの理解しやすさと整理のしやすさが向上する。特定のデータに関する操作が、場当たり的に散らばるのではなく、1か所に集約される。
- コード量を減らせる。

## 無視してよい場合

- 値（プリミティブ型）だけを渡す代わりにオブジェクト全体をメソッド引数にすると、2つのクラスの間に望ましくない依存が生まれることがある。
