# Refused Bequest（拒否された遺産）

<https://refactoring.guru/smells/refused-bequest>

## 兆候と症状

サブクラスが親クラスから継承したメソッドやプロパティの一部しか使っていないなら、その継承階層はどこかちぐはぐです。不要なメソッドは単に使われないままか、再定義されて例外を投げるようになっていることもあります。

## 原因

親クラスとの継承関係が作られた理由が、単にスーパークラスのコードを再利用したかったから、というケースです。しかし実際には、スーパークラスとサブクラスは本質的に別物です。

## 治療法

- 継承に意味がなく、サブクラスがスーパークラスと本当に共通点を持たないなら、[Replace Inheritance with Delegation](https://refactoring.guru/replace-inheritance-with-delegation) で継承をやめて委譲に置き換えます。
- 継承自体は妥当なら、サブクラスに不要なフィールドやメソッドをなくします。サブクラスが必要とするフィールドとメソッドを親クラスから取り出して新しいスーパークラスにまとめ、両方のクラスがそれを継承するようにします（[Extract Superclass](https://refactoring.guru/extract-superclass)）。

## 効果

コードの見通しと構成がよくなります。たとえば `Dog` クラスが `Chair` クラスを継承している理由に悩まされることもなくなります（どちらも脚が4本あるとしても）。
