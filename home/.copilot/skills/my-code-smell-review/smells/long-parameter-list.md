# Long Parameter List（長すぎる引数リスト）

<https://refactoring.guru/smells/long-parameter-list>

## 兆候と症状

メソッドの引数が3個または4個を超えている。

## 原因

長い引数リストは、複数のアルゴリズムを1つのメソッドに統合した結果として生まれることがある。どのアルゴリズムをどう実行するかを制御するために、引数が増えていくのである。

また、クラス同士の依存を減らそうとした結果として長くなる場合もある。たとえば、メソッド内で必要なオブジェクトを生成していた処理を呼び出し側へ移し、生成済みのオブジェクトを引数で渡すようにすれば、元のクラスはオブジェクト間の関係を知らなくて済む。これは依存の低減につながるが、必要なオブジェクトが増えるたびに引数も増え、結果として引数リストが長くなる。

こうした引数リストは、長くなるほど理解しづらく、矛盾も生みやすく、使いにくくなる。長い引数を並べる代わりに、メソッドは自分自身のオブジェクトが持つデータを使える場合がある。もし現在のオブジェクトに必要な情報が足りないなら、その情報を持つ別オブジェクトを引数として渡せばよい。

## 治療法

- まず、どんな値が引数として渡されているかを確認する。もし引数の一部が別オブジェクトのメソッド呼び出し結果にすぎないなら、[Replace Parameter with Method Call](https://refactoring.guru/replace-parameter-with-method-call) を使う。そのオブジェクトは、自分のクラスのフィールドとして持たせてもよいし、メソッド引数として渡してもよい。
- 別オブジェクトから取得したデータのまとまりを個別の引数で渡しているなら、[Preserve Whole Object](https://refactoring.guru/preserve-whole-object) を使って、そのオブジェクトごとメソッドに渡す。
- ただし、引数が異なる場所から来ているなら、[Introduce Parameter Object](https://refactoring.guru/introduce-parameter-object) で1つの引数オブジェクトにまとめるとよい。

## 効果

- コードが短くなり、読みやすくなる。
- これまで見落としていた重複コードが見つかることがある。

## 無視してよい場合

- 引数を減らすことでクラス間に望ましくない依存が生まれるなら、無理に引数をなくすべきではない。
