# Parallel Inheritance Hierarchies（並行継承階層）

<https://refactoring.guru/smells/parallel-inheritance-hierarchies>

## 兆候と症状

あるクラスのサブクラスを1つ作るたびに、別のクラスでも対応するサブクラスを作らなければならない。

## 原因

継承階層が小さいうちは問題が表面化しにくい。しかしクラスが増えてくると、変更のたびに複数の階層を並行して追いかける必要が生じ、だんだん手に負えなくなる。

## 治療法

- 並行するクラス階層の重複は、2段階で整理できる。まず片方の階層のインスタンスから、もう片方の階層のインスタンスを参照するようにする。そのうえで、参照される側の階層にある振る舞いとデータを [Move Method](https://refactoring.guru/move-method) と [Move Field](https://refactoring.guru/move-field) で移し、不要になった階層を取り除く

## 効果

- 重複コードを減らせる
- コードの構成が改善されることがある

## 無視してよい場合

並行したクラス階層が、より大きな設計上の混乱を避けるための現実的な落としどころになっていることもある。重複排除を試した結果、かえって見通しの悪いコードになるなら、いったん手を引いて変更を戻し、その構造を受け入れたほうがよい。
