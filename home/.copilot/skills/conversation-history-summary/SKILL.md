# 会話要約スキル

今回の会話で、ユーザーにどのような問題や疑問があり、それに対してユーザがどのような有力な解決策や調査結果を採用したかをまとめること。

1. どういう問題点や疑問点があり、
2. それに対してどのような解決策や調査を得たか
3. その解決策の結果や調査結果は何が合ったか (これにより新たに問題点や疑問点が生まれることもある)

の繰り返しを書くこと。

## ルール

同様の疑問や問題はまとめて1箇所に書くこと。

文脈がわからない人でもどういう問題があったのかわかるよう、不要な固有名詞やプログラムの識別子名はできるだけ避けること。ただし一般的な専門用語は OK

ユーザーが明らかに言及したり、対策しようとしたり、指摘されて方針を考え直したりしていると読み取れる項目だけを抜粋すること。
会話に出てくる案、懸念、論点について、 AI が考えただけでユーザーが追っていないものは一切記載しないこと。
要約対象は「ユーザーが何を問題視し解決したか」であり、AI の試行錯誤や勝手な懸念は一切不要。

ある問題の解決策や調査結果などは、後の話に関わってきた重要なものだけを抜粋すること。
出力する文章は、上から下へストーリーや論理的な繋がりがわかるように抜粋すること。
会話履歴は長いだろうが、論理の流れを把握する上で必要最低限の情報だけを抜粋すること。
有効な解決策と思われたものの新たに発見された問題や、トレードオフなどに注意すること。

## 出力のフォーマット

おおよそ以下のような雰囲気の文章で、 markdown としてコピペできるようにコードブロックで囲って出力すること。

````
```
* 問題点: コンパイル時に `Error: Hoge` というエラーが発生した。
    * 解決策: <http://example.com/solution1> に従って、設定ファイルを修正した。
        + 結果: エラーは解消されなかった。
    * 解決策: <http://example.com/solution2> に従って、ライブラリを更新した。
        + 結果: エラーは解消されたが、別のエラー `FugaException` が発生した。

* 問題点: `FugaException` が発生し、プログラムがクラッシュした。
    * 調査: `FugaException` とは何なのか調査した。
        + 調査結果: `FugaException` は、DB接続時に発生する例外であることがわかった。
        + 調査結果: それほど問題ないことがわかった。 <http://example.com/fuga_exception>
        + 調査結果: 握りつぶしているサイトもあった。 <http://example.com/fuga_exception_ignore>
    * 解決策: `FugaException` を catch して握りつぶすようにした。

* 疑問点: `FugaException` を握りつぶしても本当に良いのか。
    * 調査: web 検索
        + 調査結果: `FugaException` は、DB接続時に発生する例外であり、DBが一時的に落ちている場合に発生することがある。
            そのため、DBが復旧すれば問題ないことがわかった。
        + 調査結果: しかし、DBが復旧しない場合は、プログラムがクラッシュする可能性があるらしい。
    * 調査: 実際に `FugaException` を握りつぶすコードに変更し、 DBを落としてプログラムを実行し、数秒後 DB を復旧させた。
        + 調査結果: `FugaException` が発生したが、プログラムはクラッシュせずに正常に動作した。
...
```
````

### 回答フォーマットのルール

* トップレベルは「問題点」「疑問点」のいずれか。1つの問題点・疑問点の中に1つだけの問題点・疑問点を記載すること。
* 「問題点」は「解決策」「調査」を含むことができる
* 「疑問点」は「調査」を含むことができる
* 「調査」は「調査結果」を含むことができる。
* 「解決策」は「結果」を含むことができる
* 「結果」として記載していいのは、実際にユーザーか AI が動作確認等を行って得られた事実、または、ユーザーによる論評や不満が会話から読み取れる場合だけ。方針、判断、整理、意図、今後の予定などは、その解決策による結果ではないため、記載してはならない。
* 「調査結果」として記載してよいのは、ユーザーまたは AI が外部ソース・公式ドキュメント・実コード・実行結果による裏付けのある事実であり、単なる AI の発言などは含めてはならない。
* 下位レベルの箇条書きに有効なものが0件の場合、その上位レベルの箇条書きも削除すること
* 上位レベルの箇条書きと下位レベルの箇条書きには論理的なつながりが必須。論理的な繋がりがあるか徹底的に検証し、各アイテムの配置を再構成しながら最適な配置を見つけること。
* 「問題点」「疑問点」「解決策」「調査」は AI が自発的に行ったものではなく、ユーザーが明示的に指示したものだけを記載すること。
