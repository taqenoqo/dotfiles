# レポート検証手順

最終レポート (`report.md`) に対して以下の検証を行い、問題があれば修正してください。

## 1. リンクの検証

レポート内のすべての URL リンクに実際にアクセスしてください。

- **アクセス可能 (HTTP 200):** そのまま残す
- **アクセス不能 (404, タイムアウト等):** リンクを削除し、テキストのみ残す
  - 例: `[Long Method](https://example.com/dead-link)` → `Long Method`
- **リダイレクト先が無関係な内容:** リンクを削除

## 2. 専門用語の検証

レポート内で使われている専門用語（特にリンクテキストや見出し的に使われているもの）について:

- **一般的に認知された用語か？** Google 検索やリファレンス（Martin Fowler, Refactoring Guru, Wikipedia 等）で確認
- **非一般的な造語・ハルシネーション用語の場合:** 最も近い一般的な用語に置き換える
  - 例: `Persistence Detail Leak` → `Leaky Abstraction` (Martin Fowler) に修正
  - 例: `Bounded Context Erosion` → 一般的でない場合は単に「境界侵食」等の平易な表現に
- **正しいが冗長な場合:** 簡潔にする

修正後、レポートを上書き保存してください。
